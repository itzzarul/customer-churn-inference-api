# Customer Churn Prediction — Real-Time ML Inference API

A FastAPI REST service that loads a trained scikit-learn Logistic Regression pipeline and returns a churn probability from customer attributes.

> **Responsible-use notice:** The supplied training file contains only 12 rows (5 churned, 7 not churned). All Basic records are labelled churned, while all Standard and Pro records are labelled not churned. This creates a serious overfitting / sampling-artifact risk. The API is an educational capstone demonstration, **not a validated production model**. Do not use its scores to make real customer decisions.

## Model and input features

- Algorithm: Logistic Regression (`class_weight="balanced"`, `max_iter=1000`, `random_state=42`).
- Numeric preprocessing: median imputation and standard scaling.
- Categorical preprocessing: most-frequent imputation and one-hot encoding (`handle_unknown="ignore"`).
- Inputs: `tenure_months`, `support_tickets`, `monthly_spend_inr`, `last_login_days`, `plan_type`.
- `customer_id` is intentionally excluded from model features.
- Target: `churned` (`1` = churned, `0` = not churned), interpreted from the supplied column name. Confirm its precise business definition and prediction horizon with the data owner.

The included artifact is fitted on all 12 supplied rows solely so the REST endpoint can be demonstrated. It is **not** a performance claim or evidence of generalisation. No reliable production evaluation, calibration, or fairness conclusion can be drawn from this sample.

## REST endpoints

### `GET /`
Returns service information and endpoint paths.

### `GET /health`
Returns service and model-load status.

### `POST /predict`
Accepts a JSON request:

```json
{
  "tenure_months": 6,
  "support_tickets": 3,
  "monthly_spend_inr": 799,
  "last_login_days": 14,
  "plan_type": "Basic"
}
```

Example response shape:

```json
{
  "prediction": 1,
  "label": "churned",
  "churn_probability": 0.73,
  "model_status": "experimental_not_validated",
  "warning": "Educational demonstration only: trained on 12 records. Do not use for real customer decisions or automated actions."
}
```

The probability shown above is illustrative only; actual output is generated by the included model artifact. The classification threshold is 0.5 for demonstration and is not a business-approved intervention threshold. Invalid fields, out-of-range values, unknown plan names, and extra fields are rejected with HTTP 422.

## Responsible deployment checklist

Before any real-world use:
1. Obtain a substantially larger, representative, permissioned dataset.
2. Confirm label definition, prediction snapshot, and outcome horizon.
3. Verify every feature is available before prediction time; prevent target leakage.
4. Use a time-based holdout and compare with a majority-class and operational baseline.
5. Evaluate precision, recall, F1, balanced accuracy, confusion matrix, calibration, and appropriate group-level error rates.
6. Set thresholds with business owners after reviewing false-positive and false-negative costs.
7. Require human review; never automate cancellation, pricing, eligibility, penalties, or service restrictions.
8. Monitor drift, errors, complaints, privacy, and rollback conditions.

## Limitations

- Only 12 rows; no meaningful claim of generalisation.
- Dataset provenance, consent/licence, collection date, label definition, and prediction horizon are not documented in the supplied CSV.
- No timestamp is available to establish temporal ordering or rule out leakage.
- Perfect association between plan type and target in this tiny sample is a warning sign, not evidence that plan type causes churn.
- Scores must not be used for customer-level action.
